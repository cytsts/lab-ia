# Spec G10 — Suite de testes ≥80% cobertura

## Contexto
A barra final exige cobertura medida nos dois lados do lab. Os números abaixo
são de medição real (2026-09-11), não meta projetada.

## Requisitos
- RF1: `pytest` (núcleo) com `--cov=labia` reportando por módulo; suíte rápida
  roda em CPU sem GPU/rede (`-m "not slow"` para as evidências que exigem runs).
- RF2: `pnpm --dir ui coverage` (vitest v8) reportando por arquivo.
- RF3: Testes derivam das specs G1–G9; critérios de produto sobre runs reais
  ficam marcados (slow/evidência) mas continuam no mesmo comando.
- RF4: Evidência de efetividade: teste de mutação documentado (G1: otimizador
  não restaurado → falha 0.0095 > 1e-6; G3: códigos zerados → perda degrada).

## Critérios de aceite
- CA1: núcleo ≥ 80% linhas — medido: **92%** (1352 stmts / 107 miss).
- CA2: UI ≥ 80% linhas — medido: **96,7%** (16 testes; entry `main.tsx`
  excluído por ser bootstrap).
- CA3: suíte completa verde sem GPU (pytest total + vitest).
- CA4: cada meta G1–G9 tem pasta própria de testes (g1..g10) com vínculo à
  spec no cabeçalho do arquivo.

## Estado medido
| Suíte | Testes | Cobertura |
|---|---|---|
| pytest (g1..g10) | 61 | 92% núcleo |
| vitest (UI) | 16 | 96,7% |

## Riscos
- cli.py só aparece em cobertura quando coberta in-process (g10 cobre).
- Cobertura ≠ correção: mutações documentadas são o contrapeso.
