# Spec G3 — Quantização (4-bit/8-bit)

## Contexto
G2 trouxe o esqueleto (int8 simétrico por linha, NF4 por blocos, empacotado).
A meta G3 exige demonstrar a técnica completa: qualidade da compressão, impacto
na perda, inferência funcional com pesos quantizados e medição honesta de memória.
Referência externa para calibração: bitsandbytes (se funcionar neste SO; senão,
comparar só com a linha de base fp32 e registrar a lacuna).

## Objetivo
CLI/API para quantizar qualquer run do lab (8-bit int, 4-bit NF4, pseudo-QAT
int8-aware) e servir inferência com o modelo quantizado, com números de tamanho
e degradação de perda registrados como artefatos do run.

## Requisitos funcionais
- RF1: `lab-ia quantizar --run <base> --modo int8|nf4 --saida <novo-run>` cria
  run derivado: pesos quantizados + `metricas.jsonl` com perda antes/depois e
  `tamanhos.json` (bytes fp32 vs quantizado, fator, bits efetivos/parâmetro).
- RF2: Bits efetivos NF4 contabilizam escala fp16 por bloco de 64 →
  4 + 16/64 = 4.25 bits/parâmetro; int8: 8 + 32/linha.
- RF3: Inferência (`gerar`) funciona no run quantizado sem materializar fp32
  permanente (dequantização no forward já existe em NoLinear; quantização pura
  usa o mesmo caminho com r=0).
- RF4: Calibração de escala por dados (opcional): `--calibrar <amostras>` usa
  percentil 99.9 do absmax por bloco em vez do absmax total (reduz outlier).
- RF5: Relatório comparativo: se bitsandbytes importar E CUDA estiver OK,
  comparar erro relativo com `bnb.quantize blockwise_8bit`; senão, registrar no
  evento "gap-externo" que a comparação não foi possível neste ambiente.

## Requisitos não funcionais
- RNF1: Quantizar run G1 completo ≤ 30 s (GPU) / ≤ 120 s (CPU).
- RNF2: Zero dependência de rede.

## Critérios de aceite (Given–When–Then)
- CA1: Dado run G1, quando `--modo int8`, então `fator_tamanho ≥ 1.9`,
  `perda_val_depois − perda_val_antes ≤ 0.05 nats` e geração funcional.
- CA2: Dado run G1, quando `--modo nf4`, então `fator_tamanho ≥ 3.2`,
  `perda_val_depois ≤ perda_val_antes × 1.10` e geração funcional.
- CA3: Dado erro de reconstrução por camada, quando medido, então o relatório
  lista `erro_relativo_por_modulo` no tamanhos.json (auditável na UI).
- CA4: Dado teste de mutação (escala trocada de bloco), quando medir perda,
  então a perda degrada ≥ 0.5 nats (prova de que o formato é carregado de verdade).
- CA5: `pytest tests/g3/` verde em CPU.

## Dependências e riscos
- Deps: G1 (run real), G2 (quant.py).
- R1: bnb no Windows/CUDA 12 pode não carregar → CA usa apenas fp32 como
  referência nesse caso (documentado, não escondido).
