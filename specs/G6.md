# Spec G6 — UI completa (Electron + Design System)

## Contexto
Tudo que existe hoje é headless (CLI/API). A barra de qualidade exige
"interface visual amistosa, coesa, navegável e responsiva" com DS documentado.
Camada TS conversa com o núcleo pela API interna (RF7 da G1) — nunca importa
Python diretamente.

## Objetivo
App Electron (shell) + SPA React/TS/Vite: dashboard de runs com curva de
perda, detalhe de métricas/MoE/tamanhos, lançamento de experimentos, log de
eventos, tema claro/escuro, Design System próprio documentado com exemplos.

## Requisitos funcionais
- RF1: `pnpm --dir ui test` roda vitest com componentes do DS e cliente de API
  (mock) — CI local do loop; `pnpm --dir ui build` gera `ui/dist`.
- RF2: Electron main (`ui/electron/main.mjs`) abre BrowserWindow carregando
  `dist/` (produção) ou dev-server (desenvolvimento); sem nodeIntegration no
  renderer; estado da janela (tamanho/tema) persistido em
  `.lab-ia/ui-estado.json`.
- RF3: DS em `ui/src/ds/`: tokens (cores AA, tipografia, espaçamento, raio,
  sombra), componentes Button, Card, Badge(status), Toast, ThemeToggle,
  SliderNum, MetricChart (SVG linhas: loss_trem/loss_val/aux), StatusBar;
  catálogo navegável em rota `/ds` com exemplos vivos; documentação
  `ui/ds/README.md`… em `ui/src/ds/README.md`.
- RF4: Telas: (a) Dashboard — lista runs (estado.json) com badges e busca;
  (b) Detalhe do run — curva de perda (metricas.jsonl), uso de especialistas
  (MoE), tabela tamanhos.json, benchmark quando existir; (c) Executar — form
  para escolher config YAML + ação (train/ajustar/quantizar/raciocinio) via
  POST `/execucao`; (d) Eventos — feed de `.lab-ia/eventos.jsonl`.
- RF5: API do núcleo ganha POST `/execucao` (spawn headless, retorna run-id;
  recusa configs fora de `configs/`) e GET `/corre/{id}/tamanhos`,
  `/corre/{id}/comparativo`.
- RF6: Responsivo: layout funciona de 480px a widescreen (grid, não pixel
  fixo); tema segue preferência e persiste.

## Requisitos não funcionais
- RNF1: Zero chamadas de rede externas (tudo local); fontes do sistema.
- RNF2: Cobertura de testes da camada TS ≥ 80% (G10 começa aqui).
- RNF3: Primeira pintura < 1s local; sem bundlers pesados além de Vite.

## Critérios de aceite (Given–When–Then)
- CA1: `pnpm --dir ui test` verde com cobertura declarada no relatório.
- CA2: Dado núcleo servindo em 8765 com runs reais, quando abrir a janela,
  então dashboard lista g1/g2/g3/g4 com badges de estado corretos.
- CA3: No detalhe de g4-moe-zero, a curva renderiza polilinha com ≥ 2 séries
  e legenda (SVG no DOM — testado por snapshot do MetricChart com dados fake).
- CA4: Alternar tema aplica `data-tema` no <html> e persiste entre reloads.
- CA5: POST /execucao com config válida inicia subprocesso e grava evento;
  config fora de `configs/` → 400 (testado na API em pytest).
- CA6: `lab-ia-ui` empacotável: `pnpm --dir ui package` gera build do
  Electron em `ui/release/` (validado na G7; aqui só o script existe).

## Dependências e riscos
- Deps: G1–G4 (runs reais p/ dados), pnpm 10.
- R1: download do binário Electron — rede disponível (medido E0).
- R2: uvicorn precisa aceitar POST + spawn → usar subprocess.Popen com
  log para arquivo; documentar limite (sem fila).
